# 21. Blob detail: a cheap inspection tier between summary and peek

## The gap

Retrieval (`09.retrieval.md`) gave the agent two ways to look at a node and,
asymmetrically, a different two for a blob:

| | summary (in listings) | prose Abstract | raw text |
|---|---|---|---|
| node | yes | `node_detail` | — (nodes have no text) |
| blob | yes | **missing** | `peek_blob` |

A blob's Abstract carries the same prose a node's does (`summary`,
`key_questions`, `key_claims`, plus the blob-only `running_summary`) — it's
computed at extraction and stored on `data_blobs.abstract` — but nothing
surfaced it. `node_detail` rejects `b:` refs by construction. So to look closer
at a blob the agent's only option was `peek_blob`, which pulls the full raw
text.

That had two bad effects: the agent over-peeked (peek was its only "look
closer" move), and peeking is the most expensive tool there is — full document
text into context, bounded by a hard cap. The agent was spending its most
expensive resource on what is really a triage decision.

## The fix

`blob_detail(blob_ref)` is the blob counterpart of `node_detail`: it projects
the same prose fields off the blob's stored Abstract. It reuses the existing
`detail_abstract` projection and a new `fetch_blob_abstract` (symmetric to
`fetch_node_abstract`), is gated by the provenance set like every other tool
(`20.retrieval_ref_integrity.md`), and has its own defensive cap
(`max_blob_detail_fetches`).

This makes the table symmetric and establishes an explicit three-tier
inspection ladder, cheapest first:

1. **summary** — free, already in every listing.
2. **detail** (`node_detail` / `blob_detail`) — the prose Abstract, on demand.
3. **peek** (`peek_blob`) — the full raw text.

The instructions are re-tiered to match: the agent inspects via detail for
triage and reserves `peek_blob` for confirming the handful of candidates it has
already narrowed down — explicitly *not* peeking by default or peeking
everything it encounters. A separate tool (rather than generalizing
`node_detail` to accept both ref kinds) keeps the codebase's one-tool-per-kind
shape and preserves `node_detail`'s `b:`-ref redirect message.
